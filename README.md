### Краткое описание проделанной работы

#### Что было сделано?

1.  Реализована консольная утилита для анализа логов NGINX с полным функционалом:
- CLI-интерфейс - реализован парсер аргументов командной строки с поддержкой обязательных параметров (--path/-p, --output/-o, --format/-f) и опциональных (--from, --to). Добавлена валидация всех параметров, проверка расширений файлов, форматов дат (ISO8601), корректные exit-коды (0 - успех, 1 - критическая ошибка, 2 - ошибка использования).
2. Парсинг логов NGINX — реализован потоковый парсер строк логов по формату `'$remote_addr - $remote_user [$time_local] "$request" $status $body_bytes_sent "$http_referer" "$http_user_agent"'`. Некорректные строки логируются на уровень WARN и пропускаются без остановки программы.
3. Обработка файлов — реализована потоковая обработка локальных файлов (.log, .txt) с построчным чтением без загрузки всего файла в память. Поддержана фильтрация по датам (--from, --to) со всеми комбинациями параметров. Добавлена обработка несуществующих файлов и URL (с логированием).
4. Сбор статистики - реализован сбор всех требуемых метрик:
- Общее количество запросов
- Средний, максимальный и 95% перцентиль размера ответа (точность до 2 знаков)
- Частота встречаемых кодов ответа
- Топ-10 наиболее часто запрашиваемых ресурсов (без учета HTTP-метода)
- Распределение запросов по датам в процентах от общего числа
- Уникальные используемые протоколы передачи данных
5. Форматирование вывода - реализованы три формата вывода:
- JSON - строго по заданной JSON-схеме с camelCase и правильной структурой
- Markdown - таблицы с метриками, ресурсами, кодами ответа, распределением по датам
- ADOC - AsciiDoc формат с таблицами и структурированным выводом
6. Обработка ошибок - реализована fail-fast логика с корректными exit-кодами, проверками существования файлов, прав доступа, валидности расширений и форматов. Программа не создает файл результата, если не удалось обработать ни одной записи.
7. Тестирование - реализованы unit-тесты для всех компонентов:
- ArgumentValidationTests - валидация CLI-аргументов, проверка всех edge cases
- LogFileParsingTests - парсинг валидных и невалидных строк логов
- StatsCalculationTests - корректность расчета всех метрик статистики
- StatsReportTests - тесты форматтеров (JSON, Markdown, ADOC)
- Все acceptance-тесты реализованы и проходят успешно
8. Архитектура - код структурирован модульно: отдельные классы для парсинга аргументов (Arguments), парсинга логов (LogParser), обработки файлов (LogFileProcessor), сбора статистики (StatisticsBuilder), форматирования (JsonFormatter, MarkdownFormatter, AdocFormatter). Все компоненты легко тестируются и расширяемы.
